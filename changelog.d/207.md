- Release notes are per-issue fragments: `changelog.d/<issue>.md` holds an issue's entry and `tools/changelog.sh assemble vX.Y.Z YYYY-MM-DD` folds them into `CHANGELOG.md` in issue order at release time, so two branches no longer collide on one file. This repository only; nothing the plugin does changes (#207).
- `tests/inventory.test.sh` pins `docs/skills-inventory.md` one line per rule, so two changes to different rules merge without a conflict and two changes to the same rule still do. This repository only (#207).
- A parameterised `skill` lease resource, with `paths` of `skills/**` and `tests/*-skill.test.sh` and one lease per skill directory, stops two issues from changing one skill at once; `/codeo:plan` leases the skills its footprint touches and records every answered overlap question in `sequenced:` as `after #M — …` or `beside #M — …`, reading `none` only when no overlap was raised, and `/codeo:init` names the workflows that hold a lease (#207).
- `/codeo:qc` records the commit it graded as `Graded base:` and a `Behind:` line when the base branch has moved; `scripts/base-moved.sh` names the graded files the base changed since, and `/codeo:close` sends the engineer back to `/codeo:qc` when it names any. A round without a `Graded base:` line closes as before (#207).
