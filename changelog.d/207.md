Shared state: each `qc.md` round gains a `Graded base:` line after a clean sync and, when the sync merged commits, a `Behind:` line (an older `/codeo:close` ignores both); a plan's `sequenced:` footprint line records every answered overlap question in four forms plus `none`; `close.md` gains a `### Round <n> — base moved` round (an older `inflight.sh` or `dossier-check.sh` reads it as an ordinary round, and an older `/codeo:close` never writes it); a project that configures the `skill` lease resource gets `skill_<name>.md` files under `.codeo/intake/leases/`; the inventory pin file is one line per rule, separated by blank lines, and only this repository's tests read it

- Release notes are per-issue fragments: `changelog.d/<issue>.md` holds an issue's entry and `tools/changelog.sh assemble vX.Y.Z YYYY-MM-DD` folds them into `CHANGELOG.md` in issue order at release time, so two branches no longer collide on one file; a caution in any fragment's `Safe to bump mid-workflow:` wins, and a leftover `## Unreleased` heading or an existing section for the version is refused. This repository only; nothing the plugin does changes (#207).
- `tests/inventory.test.sh` pins `docs/skills-inventory.md` one line per rule with a blank line between rules, so two changes to different rules merge without a conflict and two changes to the same rule conflict in the page, resolved by `bash tests/inventory.test.sh --update`. This repository only (#207).
- A parameterised `skill` lease resource, with `paths` of `skills/**` and `tests/*-skill.test.sh` and one lease per skill directory, stops two issues from changing one skill at once; `/codeo:plan` leases the skills its footprint touches and records every answered overlap question in `sequenced:` as `after #M`, `beside #M`, `rescoped` or `locked`, reading `none` only when no overlap was raised, and `/codeo:init` names the leases other issues hold and wait for (#207).
- `/codeo:qc` records the commit it graded as `Graded base:` and a `Behind:` line when its sync merged the base; `scripts/base-moved.sh` names the graded files the base changed since, and `/codeo:close` sends the branch back to `/codeo:implement` as a `— base moved` round when it names any, on every pass and also when an *Update branch* merge already holds the base, so `/codeo:qc` grades the merged tree. A round without a `Graded base:` line closes as before (#207).
