- A host command, `codeo`, works an issue from one short word in a Linux terminal. It installs with one `curl` line (`mkdir -p ~/.local/bin && curl -fsSL -o ~/.local/bin/codeo https://raw.githubusercontent.com/kbajpai/codeo/main/.devcontainer/codeo && chmod +x ~/.local/bin/codeo`), keeps the two scripts and the sandbox clones in `~/codeo`, and downloads a missing script on first use, each download to a temporary file of its own that is made executable and renamed into place. The host needs bash 4.3, `curl`, `git` and `flock`. `codeo home [--rebuild]`, `codeo issue <N> [<branch>] [--rebuild] [--container|--sandbox]`, `codeo shell home|<N> [--container|--sandbox]`, `codeo open <N> [--container|--sandbox]`, `codeo list`, `codeo rm <N> [--force] [--container|--sandbox]`, `codeo default [container|sandbox]`, `codeo update` and `codeo help` call `codeo-container.sh` or `codeo-sandbox.sh`. `issue` finds the branch from `.codeo/<N>/init.md` on origin when none is given (one match is used; none or several print one line and start nothing), through a blob-less lookup clone that is pointed at the current `CODEO_REPO_URL`, fetched before each lookup, made in a temporary directory and used under a `flock` on `~/codeo/.lookup.lock`, so two first-use commands started together are safe; an invalid branch found on origin is refused before anything runs. It chooses a container or a sandbox from the flag or the saved default. `shell`, `open` and `rm` find which of the two holds `codeo-<N>`, and `rm <N> --container` for a container that does not exist says so. `rm` of a container starts it if it is stopped, runs `git fetch --prune origin`, and removes it only when it holds no work that exists only there: uncommitted or untracked files (`git status --porcelain --untracked-files=normal`), stashes, a detached HEAD no origin branch contains, and commits on no origin branch and under no pull-request head, so a squash-merged issue is clean. A container that was running is restarted after a clean first read (which ends any shell or agent attached to it) and read again, and a change found then refuses the removal; the restart narrows the window for a write between the check and the removal and does not close it. `rm` also checks that `/workspaces` is the volume `codeo-<N>`: when it is not, the container and image are removed and the volume is kept, with a line naming `docker volume rm codeo-<N>`, and `--force` removes it too. `--force` skips a refusal and removes also when the check cannot run. `rm` reports only what it removed, says `nothing named codeo-<N> to remove` when nothing existed, warns on a failed image removal, and says the container is already removed when the volume removal fails. For a sandbox `rm` runs `codeo-sandbox.sh end` and, when that fails, prints a hint chosen by `--force`: `codeo rm <N> --force removes it anyway; its unpushed commits are kept in ~/codeo/codeo-<N>, its uncommitted work is not` without it (only when the script refused over unpushed or uncommitted work, not when it could not read or reach the sandbox), `sbx rm --force codeo-<N>` with it. With `CODEO_HOME` unset and `~/codeo` a git checkout, `codeo` stops with one line asking for `CODEO_HOME`. A relative `CODEO_CONTEXT` or `CODEO_SBX_IMAGE`, or a `CODEO_SBX` that holds a `/`, is read against the directory `codeo` was started in, and `CODEO_SBX` picks the sbx program. `codeo update` replaces `codeo` and both scripts, and a failed download changes nothing; `codeo list` shows a paused or restarting container as such; `codeo default` with a directory it cannot create prints one line. `.devcontainer/README.md` and `.sbx/README.md` describe it. It makes no change to `codeo-container.sh` or `codeo-sandbox.sh` (#133, #143).

- `/codeo:init` cuts `<type>/<N>-<slug>`, so the issue is readable from the branch (`feat/118-live-signal-leftovers-104-refresh`); `branch-name.sh` prints the number, `init` finds a workflow under way by its dossier whatever its branch is called, so a branch cut under the old shape resumes and an issue retitled after its init does too, and `claim.sh` no longer tells you to retitle an issue whose name another issue's dossier holds (#126).

The sbx script names the next step when the start script fails (F19), asks for no pin when the sandbox already exists on a rerun (F20), and has `end` name `sbx rm --force codeo-<N>` when it cannot read the sandbox (F21).
