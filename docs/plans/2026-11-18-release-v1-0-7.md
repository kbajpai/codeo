# Release v1.0.7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship codeo v1.0.7 from `main` as it stands (release PR, clean-clone test, tag, GitHub Release), then pin this project to v1.0.7 so its container and sessions run it.

**Architecture:** Two pull requests, as for v1.0.6. The release PR comes from its own branch `release/v1.0.7`, cut from `origin/main` in a git worktree: two files and no dossier, so the required `qc-verdict` check passes (it fails a head that carries a live dossier). This workflow branch carries the pin, the plan and the dossier, and `/codeo:close` opens its PR after the tag exists. Steps that are the engineer's (merges, tag push, container rebuild) are tasks that stop and wait.

**Tech Stack:** `git`, `gh`, `jq`, `awk`, `bash tests/run.sh`, `claude plugin list`.

**Spec:** `.codeo/100/init.md` (`## Outcome`: the eight acceptance criteria and the scope decision that puts #99 in this release); `docs/release-checklist.md` steps 6-8; `.codeo/100/plan.md` Q1.

```mermaid
flowchart LR
  T1[1 release PR<br/>release/v1.0.7] --> T2[2 you merge]
  T2 --> T3[3 clean-clone test]
  T3 --> T4[4 you tag + push]
  T4 --> T5[5 agent publishes<br/>Release v1.0.7]
  T5 --> T6[6 pin PR branch<br/>plugin.ref]
  T6 --> T7[7 you rebuild, agent<br/>checks version]
```

## Global Constraints

- Release scope is `main` as it stands when the release PR is opened. #70, #71, #96, #97, #98 and #99 are all closed and merged; #99 is in this release by the engineer's decision at init, which overrides the issue text's "#99 ships later". Any other issue ships later.
- The release PR changes `.claude-plugin/plugin.json` (`version`) and `CHANGELOG.md` only; `.claude-plugin/marketplace.json` carries no version.
- The changelog heading is `## v1.0.7 — <date>`, the day the PR is opened (corrected before merge if it merges on a later day). Its `Config schema: 1`, `Shared state:` and `Safe to bump mid-workflow: yes` lines stay as written: they were checked at planning against `docs/dossier.md`, the dossier checker and the script changes since v1.0.6, and name the two additions (`.codeo/intake/cleanup/`, `refs/codeo/live/<issue>/<machine>`) with no dossier convention changed. Bullets are released as they stand, including any that merged to `main` before the PR is opened.
- **Another workflow touches `CHANGELOG.md` (plan Q1 = proceed and coordinate).** #118 (`feat/live-signal-leftovers-104-refresh`, kbajpai, at plan) will add a bullet under `## Unreleased`. It is not waited for. If it merges before the release PR is opened, its bullet ships in v1.0.7; otherwise it must write its bullet under a new `## Unreleased` above `## v1.0.7`, not under `## v1.0.7`, since git merges that edit silently. The release PR body says so, and `implement.md` records it.
- The tag push, both PR merges and the container rebuild are the engineer's. The agent never merges or tags. The agent publishes the GitHub Release only after the engineer says the tag is pushed. A pushed tag is never moved.
- The tag is lightweight, as `docs/release-checklist.md` step 7 writes it and as `v1.0.5` and `v1.0.6` are: `git tag v1.0.7 <SHA>`.
- The pin moves only after the tag exists: `.devcontainer/scripts/plugins.sh` checks the pin on GitHub before replacing codeo.
- The GitHub Release follows checklist step 8: title `v1.0.7`, notes are the changelog section only, never `--generate-notes`. Earlier Releases are titled `release: vX.Y.Z`; they are not retitled.
- Tasks 2, 4 and 7 mark `Runs on: the engineer's host`; their commands are single commands a shell passes through unchanged (the lock's host is `container`).
- No shared environment, so no task carries `Needs lease:`. No invariants document, no `wiki` module, no exclusive resources, so nothing is leased.
- Documentation: this change moves no page. No page describes a version or the pin as current; `docs/dev-environment-sbx-evaluation.md` names `1.0.6` only as recorded observations, which stay as observed. Changing the release checklist is out of scope (issue).
- `/codeo:close` opens one PR per workflow from this branch; the release PR is opened by `/codeo:implement` from `release/v1.0.7` and is a different head.

## Review Focus

- The release branch is cut from `origin/main`, not from this branch: a diff beyond two files, or any `.codeo/` change, fails `qc-verdict` and drags a live dossier into `main`.
- The clean-clone test must run at the merge commit, not at `main`'s tip if `main` moved after the merge.
- `main` may have moved between this plan and Task 1: Task 1 reads `## Unreleased` before retitling it, and every bullet there ships. Criterion 2 is re-read then: each of #70, #71, #96, #97, #98 (and #99) must appear.
- A lightweight tag has no `^{}` line in `git ls-remote --tags origin`: criterion 5 is read from the plain `refs/tags/v1.0.7` line, and `gh release create --verify-tag` is the check that the tag exists.
- The Release notes file must not start with the heading and must not be generated: `gh release view v1.0.7 --json body` holds the changelog section only.
- A stale `CODEO_ROOT` or an old session: the version check runs in a session started after the rebuild, and `claude plugin list` shows a user-scope and a project-scope `codeo@codeo`; Task 7 records either one that is not 1.0.7.

### Task 1: Open the release PR from `release/v1.0.7`

**Files:**
- Modify: `.claude-plugin/plugin.json:3` (`version`)
- Modify: `CHANGELOG.md:3` (`## Unreleased` heading)
- Worktree: `../codeo-100-release`, branch `release/v1.0.7` from `origin/main`

**Interfaces:**
- Produces: PR number `<RPR>` for Task 2, and the branch `release/v1.0.7` on origin.

- [ ] **Step 1: Cut the branch in a worktree**

Run: `git fetch origin && git worktree add -b release/v1.0.7 ../codeo-100-release origin/main && git -C ../codeo-100-release log --oneline -1`
Expected: the tip of `origin/main` (`2dabf1f`, or later if `main` moved).

- [ ] **Step 2: Gate and criterion 2 check**

Run: `for i in 70 71 96 97 98; do gh issue view $i --json state -q .state; done` and, in the worktree, `for i in 70 71 96 97 98 99; do grep -c "#$i" CHANGELOG.md; done`
Expected: five lines `CLOSED`, then six counts each at least `1`. A different result stops the task: say which issue is open or missing a bullet.

- [ ] **Step 3: Run the failing check**

Run: `cd ../codeo-100-release && jq -e '.version == "1.0.7"' .claude-plugin/plugin.json && grep -q '^## v1.0.7 — ' CHANGELOG.md`
Expected: FAIL (exit 1; version is `1.0.6`, no such heading).

- [ ] **Step 4: Make the two edits**

Set `version` to `"1.0.7"`; retitle line 3 `## Unreleased` as `## v1.0.7 — 2026-11-18` (the opening day). Read `sed -n 1,12p CHANGELOG.md` first and touch nothing else.

- [ ] **Step 5: Run the check and the suite**

Run: `jq -e '.version == "1.0.7"' .claude-plugin/plugin.json && grep -c '^## v1.0.7 — ' CHANGELOG.md && ! grep -q '^## Unreleased' CHANGELOG.md && git diff --name-only origin/main && bash tests/run.sh | tail -1`
Expected: `true`, `1`, then exactly `.claude-plugin/plugin.json` and `CHANGELOG.md`, then `all cases passed`.

- [ ] **Step 6: Commit, push, open the PR**

```bash
git add .claude-plugin/plugin.json CHANGELOG.md
git commit -m "release: v1.0.7"   # trailer: Co-Authored-By per the session's attribution
git push -u origin release/v1.0.7
gh pr create --base main --title "release: v1.0.7" --body-file <body>
```
Body, following #77: patch release; config schema 1, shared state as the changelog's line, safe to bump mid-workflow; one line per change group (the five gating issues #70, #71, #96, #97, #98 and #99); "After merge: tag `v1.0.7` on the merge commit"; the coordination note for #118 from Global Constraints; the PR attribution footer.
Proof: `gh pr view <RPR> --json baseRefName,files --jq '[.baseRefName, ([.files[].path]|sort)]'` prints `["main",[".claude-plugin/plugin.json","CHANGELOG.md"]]`, and `gh pr checks <RPR>` shows `tests` and `qc-verdict` passing.
