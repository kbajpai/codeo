# Release v1.0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship codeo v1.0.4 from `main` (release PR, clean-clone test, tag, GitHub Release), then pin this project to it so its container and sessions run it.

**Architecture:** Two pull requests, as intake Q3 settled. The release PR comes from its own branch `release/v1.0.4`, cut from `main` in a git worktree: two files and no dossier, like #33, so the required `qc-verdict` check passes (it fails a head that carries a live dossier). This workflow branch carries the pin change and the dossier, and `/codeo:close` opens that second PR after the tag exists. Steps that are the engineer's (merge, tag, Release, container rebuild) are tasks that stop and wait.

**Tech Stack:** `git`, `gh`, `jq`, `bash tests/run.sh`, `claude plugin list`.

**Spec:** `.codeo/61/init.md` (`## Outcome`: the six acceptance criteria); `docs/release-checklist.md` steps 6-7; plan Q1-Q3 of `.codeo/61/plan.md`.

## Global Constraints

- Release scope is `main` as it stands; open issues (#40, #41, #43, #51, #52, #54, #57) ship later (intake Q4).
- The release PR changes `.claude-plugin/plugin.json` (`version`) and `CHANGELOG.md` only; `.claude-plugin/marketplace.json` carries no version.
- The changelog heading is `## v1.0.4 — <date>`, the day the PR is opened (corrected before merge if it merges on a later day). Its `Config schema: 1`, `Shared state: unchanged from v1.0.3.` and `Safe to bump mid-workflow: yes` lines stay as written (Q3 = A). Bullets are released as they stand.
- The tag push, the GitHub Release, the PR merges and the container rebuild are the engineer's (`docs/release-checklist.md`: nothing there is done by an agent). The agent never merges, tags or releases. A pushed tag is never moved.
- The tag is annotated, as `v1.0.3` is (`git ls-remote` shows `refs/tags/v1.0.3^{}` → `8e3605a`).
- The pin moves only after the tag exists: `plugins.sh` checks the pin on GitHub before replacing codeo.
- No shared environment, so no task carries `Needs lease:`. No invariants document, no `wiki` module, no exclusive resources.
- Documentation: this change moves no page. No page names a version, `README.md`'s Status reads the version from `plugin.json`, and changing the release checklist is out of scope (issue).
- `/codeo:close` opens one PR per workflow from this branch; the release PR is opened by `/codeo:implement` from `release/v1.0.4` and is a different head, not a second PR for this branch.

## Review Focus

- The release branch is cut from `origin/main`, not from this branch: a diff beyond the two files, or any `.codeo/` change, fails `qc-verdict` and drags a live dossier into `main`.
- The clean-clone test must run at the merge commit, not at `main`'s tip if `main` moved after the merge.
- `claude plugin list` shows two `codeo@codeo` entries (user and project scope), both 1.0.3 today. `plugins.sh` reinstalls the user scope; Task 6 checks whether the project-scope entry also reports 1.0.4 and stops with a finding if it does not.
- A stale `CODEO_ROOT` or an old session: the version check runs in a session started after the rebuild.
- The board check writes the live card: `board.sh set 61 ready`, then `inProgress`, must leave #61 In progress.
