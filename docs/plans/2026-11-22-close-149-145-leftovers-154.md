## Global Constraints

- **Q1 (A): `codeo` adds the line, the script is untouched.** When a failed `end` without `--force` wrote the script's no-branches refusal (its stderr holds `end <N> --force removes it anyway`), `codeo rm <N>` adds one line after it: `codeo: codeo rm <N> --force removes it anyway`. The line carries no "unpushed commits are kept" clause: that refusal fetched no branches, so nothing was set aside. `tests/sandbox.test.sh:884` already pins the script's phrase, so a reword fails the suite.
- **Q2 (A): a started container is stopped again on a certain refusal.** `container_check` is passed `--no-restart` only when `docker inspect` failed and `--force` was not given, i.e. when `cmd_rm` will refuse whatever the read finds. With that flag `container_check` stops a container it started on every return, not only a non-zero one. Reproduced at plan time (a stub `docker` whose `inspect` fails and whose `ps` lists `codeo-5 exited`): exit 1, calls `inspect, ps, start, fetch, fetch, read ×4`, no `docker stop`. The container is still started, fetched and read once, and a dirty one is still refused with the work message.
- **F12 is README only.** `no sandbox codeo-<N>`: nothing is left to remove. A missing clone: running the command again fails the same way (the script dies before it reads `--force`); the way out is `sbx rm --force codeo-<N>`, which discards whatever the sandbox holds, and which `codeo rm <N> --force` prints after the script's line when `sbx ls` still lists the sandbox.
- **Flowchart edges are qualified, not labelled partial** (as #149's Q5 chose). A failed `docker volume rm` is an error only while the volume still exists; with `--force` a container already gone is not an error.
