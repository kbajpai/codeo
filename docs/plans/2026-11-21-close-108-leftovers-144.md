# Close the #108 leftovers: overlap failures, the `## Outcome` heading, init's closing block Implementation Plan (#144)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A failed `overlap.sh` can no longer be read as "no overlap", every reader of `## Outcome` judges a given heading the same way, and `/codeo:init` names a next command after a lock was taken and a TODO printed, with `bash tests/run.sh` passing.

**Architecture:** Three independent fixes, each test first: the stop sentence in five pages and a test that pins it (Task 1), the exact `## Outcome` heading in `inflight.sh` and `dossier-check.sh` with a test that feeds one set of dossiers to all three readers (Task 2), a second closing-block paragraph and handoff row for init (Task 3), then the CHANGELOG (Task 4). `overlap.sh` and `qc-verdict.sh` keep their behaviour; no pipeline step does anything new except stop where it used to carry on.

**Tech Stack:** bash, git, awk; the `shell` suite (`bash tests/run.sh`, or one file with `bash tests/<name>.test.sh`).

**Spec:** `.codeo/144/init.md` `## Outcome` (the issue's acceptance criteria) and `.codeo/144/plan.md` Q1-Q2, whose answers are the design. Reference doc: none; `docs/handoff.md` and `docs/dossier.md` are the standing references and get documentation tasks.

## Global Constraints

- **Q1 (answered A): `## Outcome` is matched exactly everywhere** — the text `Outcome` alone, trailing whitespace allowed, as `qc-verdict.sh` already does (`/^## Outcome[[:space:]]*$/`). `## Outcomes` and `## Outcome notes` are ordinary sections to all three scripts. `qc-verdict.sh` and `overlap.sh` are not edited (the issue's out-of-scope line). `section_range` in `dossier-check.sh` keeps its "name, or name then a space" rule for every other section (`## Draft (approved)`); only `Outcome` is exact.
- **Q2 (answered A): init gets a second closing-block paragraph and a second handoff row.** `**Closing block — no lock:**` keeps its goal and steps and still never names `/codeo:plan`, so the three `lacks '/codeo:plan'` assertions in `tests/closing-exits.test.sh` stay. Init still withholds its own hand-off after any `lock: TODO` (#108's Q4); what changes is that the lock-taken case now names `/codeo:plan` as the step after the fix.
- **The stop sentence (F6).** Every page that runs `overlap.sh` carries these two sentences verbatim (the test pins them): `A non-zero exit, with an \`overlap: cannot diff …\` or \`overlap: cannot resolve …\` line, is a stop to report, never "no overlap".` and, for the pair run only, `An \`overlap: skipping #<M>'s changed paths\` warning with exit 0 is quoted to the engineer, and the step carries on with that workflow's footprint alone.` The second is my call: it is what `overlap.sh` does for another workflow's failed diff (#108 Q1, option A), and without it that warning has no reader.
- **Present tense.** The pages describe what the system does and name no issue; only `CHANGELOG.md` carries `(#144)`.
- **Documentation moves**, one task each: `skills/plan`, `skills/implement`, `skills/qc`, `skills/close`, `docs/handoff.md` (Task 1); `docs/dossier.md` and the comments in the two scripts (Task 2); `skills/init/SKILL.md` and `docs/handoff.md` (Task 3); `CHANGELOG.md` (Task 4). `docs/skills.md`, `docs/skills-inventory.md` and the rules pinned by `tests/fixtures/skills-inventory.rules.sha256` are not edited, so the skills lint must still pass untouched. No wiki module.
- **No environment, no lease, no host tasks.** No shared environment, wiki module, invariants document or exclusive resource is configured and the lock's host is `container`: every task runs in this checkout and none carries `Needs lease:` or `Runs on:`.
- **A mutation is a proof.** Where a step says "mutate", make the change in a scratch copy or revert it with `git checkout -- <file>` straight after; none is committed.
- **Invariants:** none configured.
